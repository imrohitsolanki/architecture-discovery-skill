# ISO/IEC 27001:2022 — not sourced in this build

**Status: stub.** This skill cannot produce a control mapping for ISO 27001.

**Source to read:** <https://www.iso.org/standard/27001> (the standard is paywalled)

## Why there is nothing here

Two reasons, and the second one does not go away.

The standard was not read during the build: iso.org returned HTTP 403 to a scripted
request. Recorded as `LIMITATIONS.md` L1.

More durably, Annex A is copyrighted text that is not ours to reproduce. Even with
the standard in hand, the right output here is a mapping *to* control identifiers
rather than a copy of the control descriptions. A reference file that reproduced
Annex A would be both a licensing problem and, if written from memory, wrong.

## What to do when a client names ISO 27001

1. Say plainly that this skill has no ISO 27001 control mapping, and that the
   organisation's own Statement of Applicability is the authoritative document
   anyway — it records which Annex A controls apply and why, and that determination
   is theirs.
2. Ask whether a Statement of Applicability already exists. If it does, that is the
   input, and the useful work is mapping this architecture's controls onto it.
3. Record the gap in `open-questions.md` with a named owner.
4. Continue the interview. Much of what ISO 27001 asks for in a technical estate is
   already covered by the secure defaults and by domains 8, 10, 11 and 12 — access
   control, logging, vulnerability management, backup, supplier management. Doing that
   work well is not wasted; it just cannot be labelled with control identifiers here.

`check_compliance.py` exits non-zero when this regime is named.

## To close this out

The sound approach is not to reproduce Annex A. It is to map this skill's own
proposed controls onto Annex A identifiers, with the identifier and title only, and
to point at the client's Statement of Applicability for scope. Populate the
`iso-27001` entry in `../../scripts/compliance_controls.json` on that basis, set
`"sourced": true`, and update `LIMITATIONS.md` L1.
